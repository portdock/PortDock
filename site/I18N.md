# 사이트 여러 언어 — 구조와 새 언어 붙이기

portdock.dev 는 한국어(`/`)·영어(`/en/`)가 모든 쪽을 갖고, **추가 언어**(ja·de·es·pt·pl·fr·vi·tr·it·id)는 «번역 범위» 의 쪽만 갖는다.
번역 범위 = **1차 묶음**(`SCOPE` 15쪽 — 모든 추가 언어 공통) + **2차 묶음**(`SCOPE2` 산업 웹 도구 10개)·**3차 묶음**(`SCOPE3` PC 하드웨어 테스트 웹 도구 9개)·**4차 묶음**(`SCOPE4` 통신 웹 도구 9개)·**5차 묶음**(`SCOPE5` 신호·단위·네트워크 웹 도구 12개)·**6차 묶음**(`SCOPE6` 전기 웹 도구 15개)·**7차 묶음**(`SCOPE7` 기계·배선 작업·문서 웹 도구 15개)·**8차 묶음**(`SCOPE8` 윈도우 프로그램 소개 13쪽)·**9차 묶음**(`SCOPE9` 장비 레지스터 맵 — 목록 1쪽 + 장비 86종) 중 그 언어가 번역을 끝낸 쪽(`MORE[언어]` — 2차~9차를 한 목록으로).
번역이 없는 쪽에는 그 언어 주소·hreflang·언어 고르기·sitemap 항목이 생기지 않고, 추가 언어 쪽에서 그런 쪽으로 가는 링크는 영어판으로 간다.

## 어디에 무엇이 있나

| 무엇 | 파일 |

| 5차 묶음 사전 | `src/i18n/ja/batch5.ts` — 5차 도구 12개의 이름·소개(`webTools`), 쪽 글(`pages` → `pages/<쪽>.ts`), 문구 묶음(`lib` → `lib/<묶음>.ts`) |

| 9차 묶음 사전 | `src/i18n/ja/batch9.ts` — 장비 맵 화면 공통 글(`pages.devices` 목록 → `pages/devices.ts`, `pages.device` 장비 한 종 → `pages/device.ts`), 장비 종류 이름(`kinds`), 장비마다 요약(`summaries` → `deviceSummaries.ts`, 열쇠 = 장비 id) |
| 사전 모음(빌드 때만 읽음) | `src/i18n/index.ts` (`DICTS` 1차 · `DICTS2`~`DICTS9` · `page2()`~`page9()`·`toolPage8()`·`kinds9()`·`summary9()`·`hwPrivacy()`) · 긴 본문은 `src/i18n/prose.ts` (`PROSE`) · 프로그램 소개 글 고르기 `lib/i18n.ts` 의 `appText()` |

| 가이드·웹 도구 이름(링크 글, 번역 없는 쪽은 «(英語)» 표시) | `src/i18n/names.ts` (`pageName()`) |
| 한국어·영어 공용 문구 | `src/lib/i18n.ts` (`UI`), 쪽 글은 각 `views/*.astro` 의 `lang === "ko" ? {…} : lang === "en" ? {…} : dict(lang).pages.<쪽>` |
| 계산 라이브러리 문구 찾기 | `src/lib/tr.ts` — 한국어·영어는 코드 안 `msg(lang, ko, en)`, 추가 언어는 **영어 문장 → 번역** 표 |

계산 라이브러리 표의 열쇠는 코드의 영어 문장 그대로, `${…}` 자리만 `{}` 로 쓴다. 번역에서 `{0}` `{1}` … `{10}` `{11}` 로 그 값을 순서와 상관없이 쓴다.
끼워 넣은 값이 표에 그대로 있는 영어 문구(함수 이름·단위)면 그것도 번역된다. TXD·BI_DA+ 처럼 소문자 낱말이 없는 글은 그대로 둔다 — 다만 표에 **그 글 그대로** 있으면 옮긴다(`lib/tr.ts` 는 표를 먼저 본다). `Min ms`·`Qty`·`CS on`·`no ACK` 처럼 소문자 세 글자가 없는 짧은 머리글은 시험이 요구하지 않으므로 4차 묶음 사전에 직접 넣어 둔 것을 본뜬다.
쪽에는 그 쪽이 쓰는 묶음만 JSON 으로 실린다(`Base` 의 `libText`) — 한국어·영어 쪽의 JS 는 늘지 않는다.

## 새 언어 붙이는 순서 (예: 독일어 `de`)

1. **사전 복사** — `src/i18n/ja/` 폴더를 `src/i18n/de/` 로 통째로 복사하고 글을 옮긴다. 열쇠·배열 길이·함수 모양은 그대로(바꾸면 `astro check` 와 시험이 잡는다).
   - `ui.ts` → 공용 문구(머리줄·바닥글·내려받기·이용 안내·«이 페이지가 도움이 됐나요?»). `inEnglish`·`allToolsEn` 은 «(영어)» 같은 그 언어 표시.
   - `common.ts` → 프로그램 한 줄 소개 13개, 번역 범위 웹 도구 10개의 이름·소개, 도구 묶음 이름, «무엇을 하려나요?», 파일 크기.
   - `pages/*.ts` → 쪽마다 제목(`title`)·검색 제목(`seo`)·설명(`desc`)·본문. `home`·`download`·`privacy` 는 수를 받는 함수.
   - `lib/*.ts` → 계산·해석 결과 문구. 열쇠(영어)는 건드리지 말고 값만 옮긴다.
   - `SafetyBody.astro`·`PrivacyBody.astro` → 긴 본문(링크 포함 마크업). `const lang = "ja"` 를 `"de"` 로.
2. **등록 세 곳**
   - `src/i18n/langs.ts`: `EXTRA_LANGS` 에 `"de"`, `LANG_META` 에 `de: { name: "Deutsch", hreflang: "de", locale: "de-DE", og: "de_DE" }`.
   - `src/i18n/index.ts`: `import de from "./de/index.ts"` 하고 `DICTS` 에 `de`. `DICTS` 는 `Record<ExtraLang, Dict>`(`Dict` = 기준판 ja 의 모양)라 빠진 문구·다른 모양은 `astro check` 가 잡는다.
   - `src/i18n/prose.ts`: `de: { safety: DeSafety, privacy: DePrivacy }`.
3. **주소 파일** — `src/pages/ja/[...path].astro` 를 `src/pages/de/[...path].astro` 로 복사하고 `staticPaths("ja")`·`lang="ja"` 두 곳을 `"de"` 로(시험이 본다).
4. **검사** (모두 통과해야 함)
   - `npm run test -w portdock-site` — `src/lib/i18n.test.ts`: 사전 모양이 ja 와 같은지, 빈 문구, 번역 범위 도구의 영어 문장마다 번역이 있는지, 예시 입력을 돌렸을 때 영어가 남지 않는지, `pages/<언어>/` 와 `EXTRA_LANGS` 가 맞는지.
   - `npm run check -w portdock-site`, `npm run build -w portdock-site`
   - `node tools/site-check.mjs site/dist` — 언어별 제목(66칸)·설명(70~160칸, 한자·가나·한글은 2칸) 길이, hreflang 짝(서로 같은 묶음)·자기 언어 포함, 번역 범위 = 빌드된 `/<언어>/` 쪽 = sitemap 의 `/<언어>/` 주소, sitemap xhtml:link 가 있는 쪽만 가리키는지.
   - `node tools/privacy-check.mjs site/dist`
5. 빌드된 `site/dist/de/` 쪽을 몇 개 열어 남은 영어·한국어가 없는지 본다(문서 이름·규격 이름·제품 이름은 그대로 둔다).

새 언어는 위 1~5 로 1차 묶음만 붙이면 된다 — 2차·3차 묶음은 아래 순서로 따로(쪽 하나씩도 된다). 번역 전에는 그 언어에 그 묶음 쪽이 생기지 않는다.

## 2차 묶음 붙이는 법 (예: 독일어 `de` 에 웹 도구 10개)

2차 묶음 = `scope.ts` 의 `SCOPE2`: 배선도 만들기(wiring) · 고장 원인 찾기(troubleshoot) · 멀티미터 측정값 점검(multimeterCheck) · CAN 프레임 해석(canDecoder) · CAN 비트 타이밍(canTiming) · I2C(i2c) · UART 보율 오차(uartBaud) · Modbus RTU↔TCP(modbusRtuTcp) · XGT 해석(xgtDecoder) · 케이블 선정(cableSelection).
화면(`views/*.astro`)·계산 코드는 이미 세 갈래(`lang === "ko" ? … : lang === "en" ? … : page2(lang, "<쪽>")`)라 고칠 것이 없다 — 사전만 채운다.

1. **파일 복사** — 기준판 `src/i18n/ja/` 에서 아래를 `src/i18n/de/` 같은 자리로 복사해 옮긴다(열쇠·배열 길이·함수 모양 그대로, 영어판 쪽을 원천으로).
   - `batch2.ts` — `webTools`(도구 10개 이름·소개)와 `lib`·`pages` 를 모으는 파일. 아직 옮기지 않은 쪽은 `pages`·`webTools` 에서 빼도 된다(쪽 단위로 일부만 가능, `satisfies` 는 `Partial<…>` 로).
   - `pages/` 의 10개: `wiring.ts` `troubleshoot.ts` `multimeterCheck.ts` `canDecoder.ts` `canTiming.ts` `i2c.ts` `uartBaud.ts` `modbusRtuTcp.ts` `xgtDecoder.ts` `cableSelection.ts` — 쪽 제목(`title`·`seo` 66칸)·설명(`desc` 70~160칸)·본문·FAQ. `end`·`more`·`seeG` 처럼 링크 앞뒤로 나뉜 글은 그 언어 어순으로 앞·뒤 조각을 맞춘다.
   - `lib/` 의 12개: `wiring.ts` `troubleshoot.ts` `meterCheck.ts` `meterUi.ts` `canFrame.ts` `canTiming.ts` `i2c.ts` `uartBaud.ts` `modbusConvert.ts` `xgt.ts` `xgtManuals.ts` `cableSelect.ts` — **영어 문장 → 번역** 표(열쇠는 그대로, `{}` 자리는 `{0}` `{1}` …). 같은 영어 문장은 1차 묶음(`lib/*.ts`)과 같은 번역이어야 한다(시험이 본다).
   - `troubleshootTree.ts` — 고장 원인 찾기 질문 나무의 글. **노드 id 로 찾는 표**다(나무 모양·링크는 `data/troubleshoot.ts` 하나를 모든 언어가 함께 쓴다): `yes`·`no`, 증상 8개, 질문(`q`, 나무에 힌트가 있으면 `hint`, 예/아니오가 아닌 답만 `opts`), 결과(`title`·`causes`·`checks` — 나무와 같은 수·순서). `pages/troubleshoot.ts` 가 `tree` 로 가져온다.
2. **등록** — `src/i18n/index.ts`: `import de2 from "./de/batch2.ts"` 하고 `DICTS2` 에 `de: de2`.
3. **공개** — `src/i18n/scope.ts` 의 `MORE` 에 `de: SCOPE2_PATHS`(또는 옮긴 쪽 경로만 `["tools/i2c/", …]`; 3차까지 끝냈으면 `[...SCOPE2_PATHS, ...SCOPE3_PATHS]`). 이 한 줄로 `/de/tools/…` 주소·hreflang·언어 고르기·sitemap·도구 목록·홈의 «웹 도구 n개» 가 따라온다.
4. **검사** — 위 «새 언어» 4번과 같다. `npm run test -w portdock-site` 의 2차 묶음 시험이 `MORE.de` 의 쪽마다 본다: 쪽 글이 ja 와 같은 모양·빈 글 없음, 도구 이름, 나무 글 표가 나무와 맞음(`checkText()`), 화면·라이브러리의 영어 문장마다 번역, 브라우저 스크립트가 쓰는 문장이 그 쪽이 싣는 묶음(`libText`)에 있음, 예시 입력을 돌렸을 때 영어가 남지 않음.
5. 빌드된 `site/dist/de/tools/<도구>/` 를 열어 남은 영어·한국어를 본다(규격·문서 이름, 가이드 링크의 «(영어)» 표시, 언어 고르기의 «한국어» 는 그대로).

## 3차 묶음 붙이는 법 (예: 독일어 `de` 에 PC 하드웨어 테스트 9개)

3차 묶음 = `scope.ts` 의 `SCOPE3`: 마이크 테스트(micTest) · 키보드 테스트(keyboardTest) · 웹캠 테스트(webcamTest) · 스피커 좌우 테스트(speakerTest) · 마우스 더블클릭 테스트(mouseTest) · 게임패드 테스트(gamepadTest) · 모니터 불량화소·주사율 테스트(monitorTest) · 블루스크린 정지 코드 사전(bsodCodes) · 바코드 스캐너 테스트(barcodeTest).
구조는 2차 묶음과 같다 — 묶음마다 사전 파일(`batch3.ts`)·사전 모음(`DICTS3`)·쪽 글 찾기(`page3()`)가 따로고, 공개 목록 `MORE[언어]` 는 2차·3차를 한 목록으로 쓴다(`LATER` = 2차 + 3차). 화면(`views/*.astro`)·계산 코드는 이미 세 갈래라 고칠 것이 없다 — 사전만 채운다.

1. **파일 복사** — 기준판 `src/i18n/ja/` 에서 아래를 `src/i18n/de/` 같은 자리로 복사해 옮긴다(열쇠·배열 길이·함수 모양 그대로, 영어판 쪽을 원천으로).
   - `batch3.ts` — `webTools`(도구 10개 이름·소개), `hwPrivacy`(하드웨어 테스트 7쪽이 함께 쓰는 개인정보 두 줄 — `ads`·`tester` 는 링크 앞뒤 조각), `lib`·`pages` 를 모으는 파일. 아직 옮기지 않은 쪽은 빼도 된다(쪽 단위로 일부만 가능, `satisfies` 는 `Partial<…>` 로).
   - `pages/` 의 9개: `micTest.ts` `keyboardTest.ts` `webcamTest.ts` `speakerTest.ts` `mouseTest.ts` `gamepadTest.ts` `monitorTest.ts` `bsodCodes.ts` `barcodeTest.ts` — 제목(`title`·`seo` 66칸)·설명(`desc` 70~160칸)·화면 글·FAQ·화면 스크립트 문구(`err`·`msg`·`m` 묶음). 쪽마다 덧붙은 것: 웹캠 `resDefault`, 마우스 `wheel`(휠 4방향), 모니터 `screens`(전체 화면 색 10개), 키보드 `kbAria`. `more` 는 다른 웹 도구로 가는 링크의 앞·뒤 조각(링크 글은 `weave()` 가 끼운다 — 링크 수 + 1 조각).
   - `lib/` 의 5개: `hwSignal.ts`(스피커 채널·게임패드 버튼 이름) `inputTiming.ts`(마우스 버튼 이름) `keyboardLayout.ts`(화면 키보드 배열 이름) `bsod.ts`(정지 코드 39개의 뜻·원인 후보와 볼 순서 16개) `barcode.ts`(GS1 AI 이름·풀이) — **영어 문장 → 번역** 표(열쇠는 그대로). 같은 영어 문장은 1·2차 묶음과 같은 번역이어야 한다(시험이 본다 — 예: `Serial number` 는 MC 묶음과 같게).
2. **등록** — `src/i18n/index.ts`: `import de3 from "./de/batch3.ts"` 하고 `DICTS3` 에 `de: de3`.

- **숫자 표기는 손으로 쓴 영어 방식 그대로 나온다.** 이 12개 화면 스크립트는 `Intl.NumberFormat` 이 아니라 `toFixed`·`toPrecision`(소수점 «.»)과 표의 `toLocaleString("en-US")`(천 단위 «,»)로 숫자를 쓴다 — 입력 칸도 «.» 를 받고 «,» 는 소수점으로 바꿔 읽는다. 사전의 글에서도 계산 결과와 같은 «1.22 mV»·«0.0034 bar» 로 적는다(독일어·프랑스어 등에서 본문 숫자만 «1,22» 로 바꾸면 화면의 결과와 어긋난다). 천 단위는 영어판처럼 «12,000» 또는 한국어판처럼 «12 000» 중 그 언어에서 헷갈리지 않는 쪽(독일어·프랑스어는 «12 000» 권장).
- **단위 이름은 그 나라 계량 표기**(일본어 JIS Z 8000·계량법: 重量キログラム・水柱ミリメートル(慣用)·英馬力/仏馬力)로. hp(550 ft·lbf/s)·PS(미터 마력)·전기 마력의 구별과 «관용»(conventional, 물 1000 kg/m³·수은 13 595.1 kg/m³)은 빼지 않는다. 독일어는 PS 가 일상어이므로 «metrische PS» 처럼 hp 와 섞이지 않게.
- **열전대 형 이름**은 그 나라 관용으로(일본어 «K タイプ»·«K 熱電対», 독일어 «Typ K», 프랑스어 «type K»). 형 글자(K·J·T·E·N·R·S·B)는 그대로.
- **op amp·필터 용어**는 그 나라 제조사(TI·ADI 현지 자료) 표기로: 일본어 非反転・反転・差動増幅, オープンループゲイン, ノイズゲイン, カットオフ周波数, 同相入力電圧範囲. 4–20mA 쪽은 1차 묶음 4–20mA 환산 계산기의 용어(일본어 工業値·デジタル値)와 맞춘다.
- GigE 의 `pRows` 설명·`formula` 의 «MB = 10⁶ bytes» 처럼 규격 용어(unpacked·lsb packed)는 그대로 두고 풀이만 옮긴다.

8차 묶음 = `scope.ts` 의 `SCOPE8`: `/<앱 id>/` 소개 쪽 13개(serial · modbus-slave · tcp · udp · simulator · netscan · modbus-master · scpi · plot · port-inspector · plc-simulator · hw-tester · mcp). **쪽 이름 = data/tools.ts 의 앱 id** 이고, 화면 하나(`views/ToolPage.astro`)가 13개를 그린다 — `LangPage.astro` 는 `VIEWS` 대신 `TOOLS` 에서 그 앱을 찾아 `ToolPage` 에 넘긴다.

## 묶음을 더 더할 때

웹 도구는 7차 묶음으로, 프로그램 소개는 8차 묶음으로, 장비 레지스터 맵은 9차 묶음으로 다 들어갔다. 쪽을 번역 범위에 **더할** 때(가이드·사용법·데이터 묶음 data/·code-signing·contact·terms 등 10차 묶음)는 `scope.ts` 에 경로(공통이면 `SCOPE`, 언어별이면 새 `SCOPE10` 을 `LATER` 에 펼치고(모양 적기 포함) `MORE`) + `index.ts` 의 `DICTS10`·`page10()`(lib 표가 있으면 `libOf` 한 줄) + 그 언어 사전의 쪽 글 + `LangPage.astro` 의 `VIEWS` 한 줄(한 화면이 여러 쪽을 그리면 8차의 `APPS` 처럼 따로), 그리고 그 화면(`views/*.astro`)의 `ko ? A : B` 를 세 갈래로 바꾼다(`lang === "ko" ? A : lang === "en" ? B : page9(lang, "<쪽>")`). 웹 도구를 새로 만들면 `lib/i18n.ts` 의 `webToolText` 한 줄도. 시험은 `i18n.test.ts` 의 8차·9차 묶음 시험 네 개를 본떠 더한다. `i18n.test.ts` 의 «번역 범위 밖» 예(`langsOf("guides/rs485-wiring/")`)가 새 묶음에 들어가면 다른 범위 밖 쪽으로 바꾼다. 동적 주소(`pages/[tool]/` 처럼 한 파일이 여러 쪽)는 «번역 범위의 쪽은 한국어·영어 쪽이 있고» 시험의 `page()` 가 그 파일을 알아보게 한다(8차는 tools.ts 의 앱 id 로, 9차는 `DEVICE_IDS` 로 `pages/devices/[maker]/[model].astro`). 쪽 목록을 데이터에서 만들면(9차) `scope.ts` 는 데이터 파일을 fs 로 읽고 사전은 가져오지 않는다.
5차 묶음은 화면 12개를 스크립트로 한 번에 바꿨다 — 화면마다 같은 손질이었다: `seoTitle` 의 `ko ? … : …` 를 `L.seo` 로, 빵 부스러기 «웹 도구» 를 `ui(lang).webTools` 로, `url()` 을 `link()` 로, 폼에 `data-lang`, 화면 스크립트의 `ko ? "…" : "…"` 를 `msg(lang, "…", "…")` 로, 그림 주소를 `lang === "ko" ? "ko" : "en"` 으로, 본문 안 `ko ? … : …` 글(그림 대체 글, 링크 앞뒤 글, 표 머리글)을 `L` 의 열쇠로.
6차 묶음도 화면 15개를 스크립트로 바꿨다 — 5차와 같은 손질에 더해, 여러 링크가 든 문단(`{ko ? "…" : "…"}<a>{ko ? "…" : "…"}</a>…` 이나 `{L.xNote} <a>{L.xLink}</a>. …`)을 글 조각 배열 `more`·`see` + 링크 글 배열 `moreLinks`·`seeLinks`(추가 언어는 `pageName()`)로 바꿨다 — 조각 사이 공백·마침표까지 조각에 넣어 한국어·영어 HTML 이 같게. 라이브러리의 `name[lang]` 은 `tx(name, lang)` 로(24V 전원·전선관).
바꾼 뒤 한국어·영어 쪽 HTML 이 그대로인지 바꾸기 전 빌드와 비교한다(스크립트 묶음 이름·`data-lang` 만 달라야 한다).
화면 스크립트의 문구는 `data-*` 로 넘기거나 `msg(lang, ko, en)` 로 쓰고(`document.documentElement.lang === "ko"` 금지 — 언어는 폼의 `data-lang` 으로 받는다), 그 문구 묶음을 `Base` 의 `libText` 에 넣는다. 서버에서만 그리는 문구 묶음(`meterUi`·`xgtManuals`)은 `libText` 에 넣지 않는다(쪽 JSON 이 커지지 않게). 라이브러리의 `ko ? "…" : "…"` 는 `msg(lang, ko, en)`(또는 `t(ko, en)`)로 바꿔야 시험이 영어 문장을 찾는다.
다른 도구로 가는 링크 글은 사전에 박지 말고 `pageName()` 으로 — 앞 묶음 사전에 «(영어)» 를 붙여 박아 둔 링크 글이 있으면, 그 쪽이 번역됐을 때 `pageName()` 을 쓰도록 화면에서 바꾼다(4차 묶음 때 MC·Modbus 해석기의 pcap 링크, RTU↔TCP 변환기의 연습장 링크, `PickApp` 의 pcap 이름, 5차 묶음 때 4–20mA 환산 계산기의 ADC 링크(`isTranslated()` 로 고름), 9차 묶음 때 첫 화면 `devTitle`·프로그램 소개 `toolPage.devices`(사전 글의 «(영어)» 를 10개 언어에서 빼고) 와 IO 리스트 `devices`·전력량계 펄스 `devLink`·Modbus 블록 읽기 `dLink`(화면이 늘 붙이던 표시를 `isTranslated(lang, "devices/")` 로)를 그렇게 바꿨다).

## 용어 원칙

- 그 나라 **제조사 공식 매뉴얼의 표기**를 따른다(일본어: 미쓰비시 전기 SLMP·MELSEC 매뉴얼, 옴론·키엔스 — 局番, ボーレート, パリティ, 終端抵抗, 保持レジスタ, サブヘッダ, 監視タイマ, 終了コード, デバイス点数, 一括読出し). 독일어는 DIN·NAMUR·Siemens 문서 표기 등.
- 같은 영어 문장은 모든 묶음에서 같은 번역(시험이 본다). 화면 이름(단추·칸)과 결과 문구의 용어를 맞춘다.
- 신호 이름(TXD·RTS·D0/D1)·함수 코드·규격 이름·제품 이름(PortDock Serial)은 옮기지 않는다.
- 문장은 그 언어로 자연스럽게 다시 쓴다(직역 금지). 검색 제목·설명은 그 나라 사람이 칠 검색어로.
- 번역이 없는 쪽으로 가는 링크 글에는 «(英語)» 처럼 그 언어로 «영어» 표시를 붙인다. 다른 웹 도구로 가는 링크 글은 사전에 박지 말고 `names.ts` 의 `pageName()`(문장 사이면 `weave()`)으로 만든다 — 번역 범위가 늘면 표시가 저절로 빠진다. `site-check` 가 번역된 쪽(`/<언어>/…`)으로 가는 링크 글에 표시가 남았는지 본다.
- 프로그램(앱) 화면은 12개 언어(0.11.0 부터)지만 도움말은 한국어·영어뿐이라는 사실을 감추지 않는다.

## 하지 말 것

- **기계 번역을 그대로 싣지 않는다** — 구글 스팸 정책의 scaled content abuse 예에 «번역 같은 자동 변환» 이 있다. 기계 번역을 썼다면 용어·문장을 사람이 고친 뒤에.
- **번역 안 된 쪽에 그 언어 주소·hreflang 을 만들지 않는다** — 본문이 영어 그대로인 «다른 언어판» 은 중복으로 본다. `scope.ts` 밖의 쪽을 `pages/<언어>/` 에 따로 만들지 말 것(site-check 가 실패한다). 2차 묶음은 번역을 다 싣고 시험이 통과한 쪽만 `MORE` 에 넣는다.
- 한국어·영어 쪽의 주소·canonical·문구를 바꾸지 않는다. x-default 는 영어판, `llms.txt` 는 영어 그대로.
- 계산 코드(`lib/*.ts`)를 언어별로 복사하지 않는다 — 문구만 표로.
- 그림(`/img/…`)은 한국어·영어 두 벌뿐 — 추가 언어 쪽은 영어 그림을 쓰고 alt·설명만 옮긴다.
